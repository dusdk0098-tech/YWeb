# 교육·일지 재설계안 (미승인 제안)

**상태: 제안. 승인 전 구현하지 않는다.** 인계문서 01_IMPLEMENTATION_GUIDE §6(D)·§8(EDU)의 [제안]을 실제로 무엇을 바꿀지 결정할 수 있게 나눈 것이다.

## 현재(인계문서 [코드] 요약)

- **교육:** 제목·과정표시·강사·목표·본문·시작/종료·휴게·명부(최대 200명)·개인별 수기 참석분수를 입력한다. 교육내용은 게시본을 정확한 ID·version·hash로 골라 적용한다. 내용 메타데이터는 JSON v1의 title·categoryLabel·objectives·contents뿐이다. 법정 이수나 참석 증명이 아니다.
- **일지:** 현장·날짜별 1건, 작업요약·위치·순찰·지적·개선 메모, 같은 날 점검 최대 10개를 정확 원문·hash로 참조한다. 보관·정정, 월간 기록이 있다.

## 인계문서 [제안]

- **교육:** 선택 화면에 과정·적용대상·자료판본·출처·미검토 경고를 보여 주고, "전체내용 읽기 → 명시 적용"으로 바꾼다. 적용대상·권리·현행성 검수 기록은 v1에 없는 새 메타데이터가 필요하다. 적용대상·필수시간을 검증하기 전에는 자동 이수 판정이나 수료증을 만들지 않는다.
- **일지:** 화면 흐름을 "오늘 현장 요약 → 미완료 확인 → 관찰·조치 입력 → 참조 확인 → 보관"으로 바꾼다.

## 선택지

### A안 (권장 1단계): 화면 흐름만 바꾸고 데이터는 그대로

- **일지:** 같은 데이터로 5단계 화면을 만든다.
  - 오늘 현장 요약: 같은 날의 점검·신고·TBM 건수(읽기 전용).
  - 미완료 확인: 미수락 점검, 기한이 지난 후속조치.
  - 관찰·조치 입력: 기존 입력칸.
  - 참조 확인: 기존 점검 참조.
  - 보관: 기존 보관.
- **교육:** 내용을 고를 때 전체 본문을 먼저 보여 주고 "이 내용 적용"을 따로 누르게 한다. 현재 있는 판본(version·hash)·과정 표시·사용중지 경고를 함께 보여 준다. 적용대상·출처 칸은 "미검토"로만 표시한다.
- DB 변경이 없고, 기존 보관본·출력은 바뀌지 않는다.

### B안 (2단계): 교육내용 검수 메타데이터 추가

- 게시본별 옆 테이블에 적용대상(자유 문구)·출처·권리 확인자·확인일·현행성 확인일을 기록한다. 기존 게시본 바이트는 그대로 둔다.
- 기록하는 사람이 입력한 사실만 저장하고, 법정 적용대상이나 필수시간 판정은 하지 않는다.
- 필요 결정: 누가 검수 기록을 남길 수 있는지(관리자만?), 검수 없이 적용할 때 경고만 할지 막을지.

### C안: 지금 유지

## 결정이 필요한 것

1. 일지: A안 5단계 흐름을 진행할지.
2. 교육: A안("전체 읽기 → 명시 적용")만 할지, B안 메타데이터까지 할지.
3. B안이면 검수 기록 권한, 미검수 적용 시 경고와 차단 중 무엇으로 할지.

## 하지 않을 것

자동 이수 판정·수료증, 교육 원자료 공개 commit, 실제 DB import, 오프라인 초안(별도 계약 필요).
