# Windows PC 검증과 로컬 수정 기록

2026-10-30. 기준 공개 커밋은 `7780f2dd2e33c8398c21b5b3e3d21d96b0a11884`, 앱 0.79.0, DB/backup 56이다. 이 기록은 격리된 복제본에서 합성 자료로 수행한 검사이며 운영 출시·안전·법적 적합성 인증이 아니다. 원격 저장소에는 이 수정본을 자동 반영하지 않았다.

## 실제 확인한 결함과 수정

- PC 본문이 긴 사이드 메뉴 높이에 따라 세로 가운데로 밀렸다. 2006px 화면에서 본문 상단이 약608px였다. 본문을 위쪽에 정렬했다.
- 320px 화면에서 전체 메뉴가 첫 화면을 차지했다. 키보드로 열고 닫을 수 있는 모바일 메뉴와 `aria-expanded`/`aria-controls`를 추가했다. 메뉴 선택 후 접히며 기존 저장하지 않은 변경·진행 중 작업 보호는 유지했다. 실제 PC 브라우저의 320px 화면에서 회의록 제목이 약360px에 표시되고 가로 넘침이 없음을 확인했다. Android 기기 검증을 뜻하지 않는다.
- A4 비용표와 긴 작업계획·점검 제목이 실제 PDF에서 잘렸다. 표/셀·제목의 줄바꿈과 셀 경계를 CSS로 수정했다. 같은673px 출력 폭에서 비용표1766px, 작업계획3768px, 점검2893px의 넘침이 모두673px로 줄었다. 과거 renderer·snapshot·receipt 바이트는 변경하지 않았다.
- Windows에서 5MiB+1 업로드가 413 대신 연결 reset으로 끝났다. 5MiB 수용 한도는 유지하고, 명시 길이의 작은 초과 요청만 무보존·별도 동시2건·1초·5MiB+64KiB 소비 상한으로 폐기 후 거절한다. 크기 불명/큰 초과/느린 요청의 즉시 종료 경로는 유지한다.
- Python ZIP 객체가 Windows 역슬래시 및 NUL 이름을 정리해 원래 경로 검증이 누락됐다. `orig_filename`을 검증하고 이름 정규화를 거부한다. fixture도 잘못된 원래 이름이 실제 ZIP에 담기도록 수정했다. 추출 기능이 없으므로 디스크 경로 이탈 쓰기 취약점으로 해석하지 않는다.
- 공지·점검·위험성평가가 같은 부모 아래 다른 구성요소에 동일한 React key를 사용해 화면 영역이 중복 생성됐다. 구성요소별 key 접두어를 부여하고 실제 DOM 개수 회귀검사를 추가했다. 공지 수신 영역은 초안→게시→후속 초안→게시에서 `1→4→6→14`였으나 수정 후 `1→0→1→0`이다. 위험성평가 출력 준비 후 검토 영역은 3개에서 1개로 정상화됐다. 업무 상태·인가·검토 기록의 의미는 변경하지 않았다.

## 자동검사

- Node24.18/npm11.16, 잠금파일 `npm ci` 성공. 당시 npm audit 발견0건은 해당 조회 시점의 결과이며 전체 보안 인증이 아니다.
- 첫 샌드박스 실행은 loopback `EACCES`로 실패했다. 허용된 외부 실행에서 환경 실패와 제품/테스트 실패를 구분했다.
- 최종 소스에서 `npm run check`: lint/typecheck 통과, **368 tests 중366 PASS/2 FAIL**, skip0. 남은2건은 변경하지 않은 `local-backup-cli.test.ts`의 POSIX0700/0600 mode assertion과 Windows symlink 생성 EPERM이다. 테스트를 제외하거나 권한을 변경하지 않았다. Windows ACL 보호 통과로 간주하지 않는다. `check`는 테스트 실패로 종료되며, 최종 key 수정 뒤 별도로 실행한 build는 통과했다.
- 업로드 관련 기존 실패 API11건, reader/폐기 제한4건, 관련 migration/backup/불변 출력14건 별도 통과. ZIP Python5건 및 Node 변환/미게시 가져오기3건 통과.
- Windows CRLF로 실패한 추출 전후 UI AST 비교는 줄바꿈만 정규화했다. 모바일 메뉴의 의도된 변경을 명시적으로 대조하며 나머지 AST와 dirty/busy 보호 비교는 유지한다.

## 브라우저 시나리오

실제 설치된 Chrome을 Playwright가 실행했다. 각 spec은 새 메모리 DB·합성 계정·loopback3107 서버를 사용한다. 기존25개 시나리오를 한 서버에서 실행하면 로그인10회/15분 제한과 충돌하므로, 로그인 제한을 완화하지 않고 실행기를 spec별 서버로 격리했다. 현재 화면과 달라진 정확한 버튼명과 accessible textbox/combobox 선택자를 갱신했으며 assertion·timeout·실패 조건은 제거하지 않았다.

첫27개 실행은14 PASS/13 FAIL, 선택자 대조 후 두 번째 전체 실행은26 PASS/1 FAIL이었다. 마지막 점검일정 제목 선택자를 고치고 실제 중복 key 결함의 DOM 회귀검사를 추가했다. 최종 소스와 빌드에서 `npm run test:e2e`는 **28 spec/28 tests PASS,0 FAIL**, exit0이다. 반응형 화면, 실제 출력 레이아웃, 신규 위험성평가 독립 작성자·검토자 및 출력 준비 흐름이 포함된다. 각 spec은 실행 결과를 따로 보존한다. 과거의 source-only 주석은 작성 당시 상태이며 실제 실행 범위는 이 문서와 검사 기록으로 구분한다.

회의록 생성/수정/목록/인쇄/로그아웃, 출역, TBM, 신고/조치, 점검 제출/독립 반려, 일정 연결, 비용·교육·장비·작업계획 등은 각 E2E의 명시된 합성 흐름 범위다. 앱 전체 인가 경쟁·모든 업무 조합·전체 접근성 수용으로 확대하지 않는다.

## PDF 및 직접 PC 조작

- 실제 빌드의 `dist/print.css`를 사용한 최종 출력 회귀 통과. 비용1쪽/점검1쪽/작업계획3쪽, A4 총5쪽을 Poppler로 렌더링해 확인했다. 정확한 세 큰 소수금액, 작업계획200자/점검500자 제목, 절차40줄과 말미 표식이 보존됐다. 큰 숫자는 셀 안에서 줄바꿈되며 반올림하지 않는다.
- 별도 연결된 PC 브라우저에서 합성 로그인, 현장 생성, 장문 회의록 저장·목록 재열기, 수정한 모바일 메뉴 키보드 열기/선택/접힘과320px 화면을 직접 확인했다.
- 직접 브라우저의 미저장 변경 확인 대화상자 처리 중 도구가 timeout/reset되어 이후 수동 정정·확정·출력은 완료로 표기하지 않는다. 합성 DB를 읽어 최초 저장 v1이 유지되고 후속 재저장이 없음을 확인했다. 별도 Chrome E2E의 결과와 구분한다.

## 독립 검토와 남은 gate

업로드 수정의 다른 검토자가 인증/인가/CSRF 순서,5MiB 수용 한도, 폐기 바이트/시간/동시성, listener·slot 회수를 확인하고 독립 stream probe를 통과했다. 실제 socket 부하·혼합 HTTP 헤더·전체 침투시험은 수행하지 않았다. 총괄은 ZIP 원래 이름 거부와 fixture diff를 별도로 검토했다. 추가 독립 UI·출력·E2E 실행기 검토에서도 범위 내 신규 차단 결함은 발견하지 못했다. 메뉴를 닫은 뒤 키보드 포커스와 실행기 부모 프로세스만 강제 종료할 때 자식 정리는 검증 한계로 남겼다. 이 추가 검토에는 위험성평가 key 수정이 포함되지 않으며 해당 수정은 총괄 diff 검토와 실제 브라우저 회귀로 확인했다.

- **SEC-LOCAL-01 P2는 미해결**이다. OS/폴더/DB/WAL/SHM/백업 권한을 자동 변경하지 않았다. Windows 백업 권한 및 symlink 회귀도 남아 있다.
- Android Studio는 설치되어 있으나 지원된 앱 실행 두 경로에서 제어 가능한 창을 얻지 못했고 실행 프로세스도 확인되지 않았다. Android 에뮬레이터 실제 검증은 미실행이다.
- 알PDF는 표준 설치 목록·경로에서 확인되지 않았고, 앞선 App Paths 조회는 권한 거부였다. 설치 여부를 확정하거나 알PDF 검증 완료로 표기하지 않는다. 공식 설치/라이선스 및 UAC가 필요한 단계는 사용자가 처리해야 한다.
- 일부 과거 출력 HTML의 모바일 viewport 누락, 전체 PDF 서식 수용, 실제 기기, 광범위 인가경쟁·복구·부하·사용자 수용 gate는 남아 있다.
- 원본 앱, R, 운영 DB, 보안/네트워크/공유 설정, 배포는 변경하지 않았다. 교육91 비공개 초안은 이 공개 소스에 추가하거나 DB에 가져오지 않았다.
