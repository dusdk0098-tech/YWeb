# 사진대지 이미지 정책 (A안 승인)

**상태: 2026-10-31 사용자가 "A안으로 진행" 승인. 한도·EXIF·첫 범위는 아래 권장값을 적용했다.** 구현: schema 60 `cost_evidence_displays`, `server/cost-photo-routes.ts`, `src/photo-display.ts`. 인계문서(01_IMPLEMENTATION_GUIDE §5·§10, LEGACY_APP_FEATURES §2)는 검역·디코딩·EXIF 정책 승인 전에 `<img>`로 사진을 노출하지 말라고 정했다. 이 문서는 그 승인 대상을 한 곳에 모은 것이다. 숫자는 모두 승인 시 바꿀 수 있는 초기값이다.

## 현재 상태(코드 근거)

- 첨부 업로드는 `server/raw-attachment.ts`: `application/octet-stream`, PNG/JPEG(일부 PDF) 헤더 바이트만 확인, 파일명 검사.
- 크기 상한 5MB(`server/bounded-upload.ts` `MAX_ATTACHMENT_BYTES`), 현장·전체 용량 한도(`attachment-quota.ts`).
- 다운로드는 `X-Attachment-Scan: UNSCANNED` 첨부 다운로드로만 제공. 화면 미리보기 없음.
- 서버에 이미지 디코더 의존성 없음(`package.json`).

## 제안 A (권장): 원본은 그대로 보관, 화면·출력은 브라우저가 만든 "표시본"만 사용

1. **원본:** 지금 첨부와 같이 바이트 그대로 보관하고 다운로드만 허용(UNSCANNED 유지). 수정·삭제하지 않는다.
2. **표시본:** 사용자의 브라우저가 원본을 `createImageBitmap(file, { imageOrientation: "from-image" })`로 디코딩하고, EXIF 방향을 적용한 뒤 canvas로 JPEG를 다시 만들어 함께 올린다. 다시 인코딩하므로 EXIF(위치·기기 정보 포함)는 표시본에 남지 않는다.
3. **서버 검사(표시본):** JPEG 헤더 확인, SOF 마커에서 가로·세로를 읽어 상한 확인, 크기 상한 확인. 디코딩은 하지 않는다(새 의존성 없음).
4. **노출:** 표시본만 `<img>`로 보여 준다. 같은 현장 구성원만 조회할 수 있고, `Content-Type: image/jpeg`, `X-Content-Type-Options: nosniff`, 기존 CSP를 유지한다.
5. **촬영일:** 브라우저가 EXIF 촬영일을 읽어 **입력칸의 기본값으로만** 채운다. 사용자가 확인·수정하며, 위치(GPS)는 읽지도 저장하지도 않는다.
6. **scene:** 원본과 별도로 사진ID·회전(90도 단위)·정규화 강조좌표·caption·순서·포함 여부·layoutVersion을 저장한다(인계 [제안] 그대로). 마감·보관본은 scene과 표시본 hash로 고정한다.

### 초기 한도(승인 대상)

| 항목 | 초기값 | 근거 |
|---|---|---|
| 원본 1장 크기 | 5MB | 기존 첨부 상한 재사용 |
| 표시본 긴 변 | 2048px | 사진대지 1쪽 2칸 인쇄에 충분, 메모리 절약 |
| 표시본 픽셀 상한 | 2048×2048 | 서버가 SOF로 확인 |
| 원본 픽셀 상한(브라우저 디코딩 전) | 50MP | 브라우저 메모리 보호, 넘으면 "너무 큰 사진" 안내 |
| 사진대지 1건 사진 수 | 40장 | 1쪽 2칸 기준 20쪽 |

## 제안 B: 서버에서 디코딩

서버가 원본을 디코딩·재인코딩한다. 신뢰는 더 높지만 이미지 처리 의존성(예: sharp, 네이티브 바이너리)을 새로 넣어야 하고, 격리 처리·시간 제한·취소 계약이 먼저 필요하다(인계 §10). 의존성 승인과 독립 보안검토가 필요해 A보다 늦어진다.

## 제안 C: 표시하지 않음

사진대지를 텍스트 목록·순서·caption만으로 만든다. 원본 사진은 다운로드로만 본다. 원본 SC의 사진대지 출력과 동등하지 않다.

## 결정이 필요한 것

1. A / B / C 중 선택.
2. 위 초기 한도 승인 또는 수정.
3. 원본에 남는 EXIF(GPS 포함)를 원본 그대로 둘지, 업로드 때 원본도 EXIF 없는 사본으로만 받을지. 권장: 원본 보존(인계 "원본사진 삭제/손실 없이"), 표시본·출력에서만 제거.
4. 첫 수직 구현 범위. 권장: 비용 원장의 SC 사진대지(1쪽 2칸 HTML 인쇄). 독립 사진 보드(N)의 원형 강조·undo는 그다음.
   - 적용: 원본 SC와 같이 사진마다 분류 4종(신호수·안전보호구 등·안전시설비 등·기타 사진대지)·촬영일·내용을 두고 분류별로 출력한다. 지출 연결과는 별개(원본 SC도 별개). 원본의 삭제 대신 "사진대지에 포함" 해제(원본 보존).
   - EXIF 촬영일: 원본의 DateTimeOriginal(없으면 DateTime)을 표시본 저장 직후 촬영일 입력칸 값으로만 채운다. 사용자가 수정 가능, GPS는 읽지 않음.
   - 미적용: 90도 회전·순서 직접 지정(분류→촬영일 순).

## 승인 후에도 PASS로 표시하지 않을 것

알PDF 실제 출력, 모바일 실기기, 8방향 EXIF 실제 사진 확인, 독립 보안검토(인계 02 §검수: 이미지 디코딩 변경은 재검토 대상).
