# 남은 기능 영역 사양안 (기타 항목 승인 후 1단계: 사양 확정)

**상태:** 2026-10-31 사용자가 "기타 항목"을 승인했다. 인계문서(01_IMPLEMENTATION_GUIDE §3·§4·§7·§10, 02 요구 표)는 이 영역들을 **사양·근거 확정 뒤** 구현하라고 정했다. 이 문서는 영역마다 인계문서의 [제안]을 첫 수직 구현 단위로 좁히고, 구현 전에 사용자가 정해야 할 값을 모은다. 아래 "결정 필요"가 채워지는 영역부터 하나씩 구현한다.

권장 순서: ① MOB-01(QR 참여, 공학 근거 불필요) → ② P-01(문서 1종씩) → ③ SC-04(AI, 끈 상태 기본) → ④ 오프라인 → ⑤ WEB-01 → P-02(전문가 검토 후).

## ① MOB-01 — QR 참여·직접 서명·동의 위치

**1단계 구현(2026-10-31, 본인 확인 = 이름+생년월일 결정):** schema 63 `worker_identities`(생년월일은 scrypt 솔트 해시만), `activity_invitations`(토큰 해시만, 2시간 만료, 1회 폐기, TBM 내용 hash 결속), `participation_events`(추가 전용, 초대·인원당 1건). 관리자가 명부에서 생년월일 등록 → TBM 편집에서 "참여 링크 만들기"(토큰은 URL `#` 뒤에만, 서버 로그 미전달) → 근로자가 로그인 없이 `/join`에서 이름+생년월일 확인 → 참여 기록. TBM 참석 상태는 자동으로 바뀌지 않는다. 잘못된 시도는 링크당 15분 10회 제한. QR 이미지: 사용자 승인으로 `qrcode` 1.5.4(MIT) 추가, 링크 발급 시 화면에 QR 표시. **2단계("권장대로" 결정):** schema 64 `consent_records`·`signature_records`(추가 전용, 3년 보존일 기록). 참여 화면에서 동의문(초안 v1, 소유자 문구 확인 대기)을 보고 손서명 후 제출하거나, 동의하지 않고 참여만 기록. 서명 PNG는 TBM 문서 hash에 결속, 관리자 화면에서 확인. 위치 확인은 권장대로 하지 않음. 3년 경과 파기는 별도 승인 필요(미구현). 남은 것: **실제 휴대폰 사용은 이 앱이 127.0.0.1에만 열려 있어 운영 배포(HTTPS·네트워크) 승인 전에는 불가.**

- **첫 단위:** TBM 1종에 대해 관리자가 만료 있는 QR 초대를 발급 → 근로자가 앱 설치 없이 열어 이름 확인 → "참여 기록"을 남긴다. 서명·위치는 2단계.
- **설계(인계 [제안] 그대로):** `activity_invitations`(현장·활동·문서 hash·만료·폐기), `participation_events`(대상·행위·시각·문서 hash). 원래 토큰은 hash만 저장하고 URL 로그에 남기지 않는다. QR만으로 신원·참석 완료를 증명하지 않으며, TBM 명부 반영은 관리자가 명시적으로 고른다.
- **결정 필요:**
  1. 본인 확인 수준: 이름+생년월일 끝자리 / 명부 선택만 / 휴대폰 인증(외부 서비스, 비용·개인정보 승인 필요).
  2. 초대 만료 시간 기본값(예: 2시간)과 1회용 여부.
  3. 대리 입력 허용 여부와 표시 방법.
  4. 동의문 문구·보존기간(서명·위치 단계에 필요).

## ② P-01 — 작업계획 문서 확장

**1단계 구현("권장대로"):** 원본 P 상세설계(`pedit-p-source` docs/DETAILED-DESIGN.md, src/shared/form-modules.ts)를 읽기만 하여, 아직 없던 계산 없는 유일한 문서인 원본 시트 1 "양식사용 체크리스트"를 추가했다. 17개 양식 모듈(정책 FORM-POLICY-2026.07.1)의 포함 여부·메모를 작업계획별로 저장(schema 65 `work_plan_form_checklists`, 작성자·작성 중에만 수정, 보관 후 고정)하고 인쇄한다. 필수 2종(일반 작업계획·위험요인 참고)은 제외 불가. 나머지 계산 양식(시트 3·5·14~20)은 P-02 전까지 보류.

- **첫 단위:** 원본 17종 중 1종을 골라 입력·단위·필수조건·출력 영역을 대조표로 만든 뒤 strict discriminated union 한 종류로 추가한다(기존 `general_machine`·`excavator_lift`와 같은 방식). 계산·안전 판정 없음.
- **결정 필요:**
  1. 첫 문서 종류(원본 P 앱의 17종 목록에서 선택).
  2. 원본 P 소스 위치(로컬 `pedit-p-source` 등) 사용 승인.

## ③ SC-04 — 선택형 AI

- **첫 단위:** 끈 상태가 기본인 "지출 내역 문구 제안" 1기능. 사용자가 버튼을 누를 때만 실행하고, 결과는 diff로 보여 준 뒤 사용자가 적용한다. 원장 변경·마감·회계 판단은 하지 않는다. AI를 꺼도 모든 기능이 동작해야 한다.
- **결정 필요:**
  1. 제공자·모델(예: Anthropic Claude)과 API 키 보관 방식.
  2. 외부로 보내도 되는 필드(지출 내용만? 금액 포함?)와 개인정보 제외 규칙.
  3. 월 비용 상한.

## ④ 오프라인 초안·동기화

- **첫 단위:** 일지 1종만 브라우저 오프라인 초안 → 재접속 시 서버 버전 비교 → 충돌이면 diff 재검토(조용히 덮어쓰지 않음).
- **결정 필요:**
  1. 기기 저장 암호화 방식과 공용 기기 로그아웃 시 삭제 정책(인계: 이것 없이 IndexedDB 저장 금지).
  2. 초안 보존기간.

## ⑤ WEB-01 — 커뮤니티·자료실·배포 목록·뉴스/날씨

**1단계 구현("권장대로"):** 메뉴 "현장 자료실"(현장 구성원 전용). 관리자가 PDF·PNG·JPEG(5MB)를 제목·판 표시와 함께 올릴 때 "저작권·사용 허락 확인" 체크가 필수이고 확인자 이름을 남긴다. 구성원은 미검사 원본을 내려받는다. 삭제 없이 사유 있는 게시 중지만(schema 66 `library_files`). 현장당 200개, 첨부 용량 한도 합산. 외부 공개·뉴스·날씨는 제외.

- **첫 단위:** 현장 내부 "자료실"(관리자 게시, 파일 권리·버전·검역 상태 표시, 구성원 다운로드). 외부 공개 커뮤니티·광고·외부 SDK는 제외.
- **결정 필요:**
  1. 외부 공개 여부(현장 구성원 전용 권장).
  2. 파일 권리 확인 책임자.
  3. 뉴스·날씨 공급원(외부 API, 승인 필요).

## P-02 — 공학 계산 (보류)

인계문서의 차단 근거(계수 0.85/1.3/0.5/1.5/1.4, 고정 1.16, ton/㎡와 kN/㎡ 의미 등)가 **독립 전문가 검토로 확정되기 전에는 구현하지 않는다.** 필요한 것: 검토자, 확정된 식·차원·계수·적용범위, 정상/경계/오류 정답 예제.

## 이 문서가 아닌 것

구현 완료 기록이 아니다. 법적 효력·본인 확인 수준·개인정보 처리 방침을 정하지 않는다.
