# Y웹 UX/UI·디자인 전면 개편 — 컨설팅과 실행 계획

## Context (왜 하는가)

사용자 판단: "AI로 급조한 티가 난다. 색과 디자인이 대충 만든 분위기, 사용 흐름도 개선 필요." 직접 확인한 결과 같은 판단입니다. 기능은 60개 화면(Panel 37 + Editor 23)으로 많지만, 공통 디자인 기반이 없어 화면마다 모양이 다르고, 개발 중 안전장치로 넣은 면책 문구·내부 ID가 사용자 화면에 그대로 노출됩니다. 목표는 **현장 안전관리자가 매일 쓰는 도구처럼 보이고 움직이게** 만드는 것이며, 서버·데이터·보안 동작은 건드리지 않습니다.

## 2. 방향 — 디자인 컨셉

**"Field Desk(현장 책상)"를 웹·모바일용으로 번안.** 같은 제품군의 데스크톱 앱 PEDIT NEXT(`dusdk0098-tech/PEDIT-N-source/DESIGN.md`)가 이미 정의한 디자인 계약으로, 토큰·규칙이 구체적이고 지금 문제와 정확히 반대 방향입니다.
- 금지: 화면을 채우는 선택 카드, 중첩 카드, 장식 패널, 큰 라운딩, 그라데이션, **영문 eyebrow와 장식 뱃지**, 설정이 본문보다 강해 보이는 구성.
- 원칙: 색만으로 상태를 말하지 않고 색+아이콘+글자를 함께. 본문 대비 4.5:1. 글자 12px 미만 금지. 라운딩 2~4px. 버튼 44px.
- 톤: 제도판·현장 기록지처럼 직선적이고 밀도 있게. 마케팅 문구 없음.

**색 토큰(제안, 사용자 결정 1에 따라 primary만 바뀜)**
- 바탕 `#F2F3F1` / 문서·카드 `#FFFFFF` / 앱 크롬 `#E7E9E7`
- 잉크 `#171C1F`, 보조 `#4E5A60`, 테두리 `#59666C`(클릭 가능) · `#B9C1C3`(구분선)
- primary **`#005EC4`**(PEDIT 로고 블루, 사용자 결정), hover `#004A9C`, 선택 바탕 `#E3EEFB`
- 주의 `#C88800`/`#FFF1C7`, 성공 `#236647`, 오류 `#A62924`/`#F9E5E3`, 포커스 `#0A66C2`

**글꼴:** `Pretendard Variable`(OFL) 자체 호스팅 → `Malgun Gothic` → `Segoe UI`. 앱이 오프라인 PC에서 돌므로 CDN 금지. 새 폰트 파일 추가는 의존성 승인 사항(결정 4).

## 4. 사용 흐름 개선

1. **홈 = 오늘 할 일.** 내가 작성 중인 초안, 내 확인을 기다리는 제출(점검·작업계획·일지), 오늘 TBM 유무, 열려 있는 비용 월·마감 임박. 1차는 기존 목록 API를 클라이언트에서 모아 표시(서버 변경 없음); 느리면 2차에 요약 엔드포인트.
2. **3단계 흐름 통일:** 목록 → 작성·편집 → 확정(제출/보관). 상태 칩 문구 통일: `작성 중 · 제출됨 · 확정 · 보관 · 정정 초안`. 확정 동작 버튼은 화면 하단 고정 액션 바 1곳.
3. **문구 정책(용어집 `docs/UI_GLOSSARY.md` 신설)**
   - 화면당 안내 1줄, 나머지는 `자세히` 접기(`<details>`). 법적 의미가 있는 문장은 삭제하지 않고 접기만.
   - UUID·SHA256·버전·JSON 이력 → "기술 정보" 접기 블록.
   - 용어 치환 예: 참조 취합→"내용 확정 준비", 명시 연결목록→"연결된 지출", 미검사 원본→"원본 파일", 보관→"확정 보관".
4. **피드백 통일:** 저장 결과는 상단 고정 상태줄(토스트) 하나로. `role="status"/"alert"`는 접근성 때문에 유지하되 위치·모양을 통일. `window.confirm`은 1차 유지(E2E가 dialog에 의존), 2차에 공통 확인 다이얼로그로 교체.
5. **긴 폼:** 섹션 번호를 살려 접기 가능한 섹션 카드 + 우측(PC)/상단(폰) 섹션 이동 링크. 폰에서는 저장 버튼을 하단 고정.
6. **로그인:** 로고 + 폼만. 마케팅 문구·영문 eyebrow 제거.

## 7. 위험과 제약

- E2E 40개가 버튼 이름·라벨 문구에 의존 → 접근성 이름은 유지하거나 PR 안에서 spec을 같이 고친다. 서버 테스트 399개는 영향 없음.
- `AGENTS.md`: 면책·법적 판정 아님 문구는 **삭제 금지, 접기만**. 공학 경고(P-02)는 화면 상단 유지(사용자 결정).
- 새 의존성은 폰트 파일뿐(승인 필요). UI 라이브러리(MUI 등) 도입 안 함 — 의존성만 늘고 문구·구조 문제는 그대로.
- 전면 재작성 금지: 60개 화면의 버전 충돌·불변 기록·권한 로직이 화면 코드에 있어 조용히 깨질 위험. 부품 교체 → 셸 → 화면 순으로 점진 적용.

## 개편 뒤 검토에서 정한 것 (2026-11-01, 2차)

6. **광고는 유지하고 제대로 만든다.** 개발자 수익용. 외부 광고 스크립트(애드센스 등)는 쓰지 않는다 — CSP를 풀어야 하고, 설치 PC가 오프라인일 수 있고, 현장 데이터 유출 의심을 사기 때문. 구성: 별도 저장소 `yweb-ads`(GitHub Pages)에 `ads.json`(제목·한 줄 문구·링크·이미지 파일명·게시 시작/종료일)과 이미지만 둔다. **설치된 앱의 서버**가 하루 한 번 받아 형식·크기를 검사하고 데이터 폴더에 저장, 화면은 `/api/ads`로 자기 서버에서만 받는다(CSP 그대로, 오프라인이면 마지막 광고). 글·이미지·링크만, HTML/스크립트 금지. 추적 없음: 나가는 요청은 목록 요청 하나, 현장·계정 정보 없음, 클릭 집계는 링크 UTM으로 광고주 쪽에서. `ADS_ENABLED` → 설정 화면 "광고 표시"(기본 켬, 끄는 자리에 후원 안내 한 줄). README·앱 안내에 무엇을 어디서 받는지 적고, 기존 "외부 광고/추적 없음" 문구를 고친다. 관리 도구는 JSON 편집 + GitHub Actions 검사로 시작.
7. **AI 문구는 "문장 다듬기"로 확장.** 일지(작업 요약·안전 안내), TBM(안전 전달사항), 회의록(결정 사항)에 버튼 추가. 쓴 글을 고쳐 주기만 하고 내용 생성·안전 판단은 하지 않는다. 설정 화면 유지.
8. **메뉴 합치기(데이터는 그대로).** 위험성평가 조치 → 위험성평가 안의 탭. 공지 + 자료실 → "공지·자료" 한 화면 두 종류. 보호구는 입구 하나(업체·보호구의 지급·반납과 재고의 보호구 이동을 한 화면에서 연결).
9. **비용 월 화면은 매달 쓰는 4개(지출 입력·원본 연결·마감·사용내역서 인쇄)만 앞에, 나머지(프리셋·기준본·분할·TSV·항목별 상세·변경 이력·인건비·대시보드)는 "고급"으로 접는다.** 기능 삭제 없음. 접힌 버튼을 누르는 E2E는 고급을 먼저 펼치도록 수정.
10. **계정 발급.** 계정이 0개면 설치 PC 브라우저에서만 "첫 운영자 만들기". 운영자는 설치 PC 화면에서 계정 발급·비밀번호 초기화·"계정 발급 권한" 부여/회수. 권한을 받은 현장 관리자는 현장 관리에서 자기 현장에 들어갈 계정을 발급하고 그 계정의 비밀번호를 초기화한다. 누가 언제 발급·초기화했는지 기록. 명령줄 발급은 유지. 외부 접속에서는 운영자 기능 불가(`isLocalRequest` 재사용).
11. **관리자가 1명인 현장: 본인이 작성과 동시에 처리까지 끝낸다.** 현장 관리자가 1명뿐이면 점검 제출·신고 조치 제출·작업중지 재개·회의 후속조치 보고·위험성평가 문서 제출이 그 한 번의 동작으로 수락/종결/확인까지 된다(두 번째 클릭 없음). 기록과 인쇄물에 "본인 처리 · 관리자 1명 현장"과 처리 계정·시각을 남긴다. 관리자가 2명이 되면 자동으로 "다른 관리자가 처리" 규칙으로 돌아간다. 앱은 이를 전자서명이나 법적 승인으로 표시하지 않는다(기존 문구 유지). 서버 규칙·권한 테스트·인쇄 템플릿을 함께 바꾼다.
12. **교육 카탈로그는 관리 기능을 접는다.** 목록엔 제목·과정·최신 판본만. 검수 기록·사용 중지·출처는 "관리" 안으로. 권리·현행성 확인 기록이므로 없애지 않는다.
