# UX/UI 전면 개편 컨설팅

**상태: 제안(미승인).** 2026-10-31 사용자 요청: "현재 너무 대충 만든 분위기가 풍기는 색상과 디자인 — 사용 흐름도 개선하고 방향·방안·방법을 세부적으로 컨설팅." 아래 수치는 모두 이 저장소의 현재 코드와 합성 서버 화면 캡처(PC 1440×900, 휴대폰 390×844)에서 직접 센 값이다.

## 1. 진단 — 왜 "급조한 티"가 나는가

원인은 하나다: 기능을 하나씩 붙이며 화면마다 개별로 만들었고, **공통 디자인 기준(토큰·컴포넌트·문구 원칙)이 한 번도 정해지지 않았다.**

## 2. 방향 — "현장 기록 도구" (원본 PEDIT `Field Desk` 계승)

원본 PEDIT NEXT `DESIGN.md`의 원칙을 웹앱에 맞게 이어받는다.

1. **현장에서 빨리, 사무실에서 정확히.** 휴대폰 = 오늘 할 기록(TBM·일지·점검·사진), PC = 문서·비용·인쇄. 같은 데이터, 기기별로 다른 첫 화면.
2. **내용이 주인공.** 기록·사진·문서가 가장 강하고, 도구·경고·메타는 한 단계 약하게.
3. **분명한 경계와 높은 대비.** 연한 색 겹치기 대신 선명한 선·흰 면·한 가지 주 색. 본문 대비 4.5:1, 경계·아이콘 3:1 이상.
4. **장식 금지.** 영문 eyebrow, 장식 배지, 카드 안의 카드, 그라데이션, 큰 둥근 모서리, 의미 없는 화살표 없음.
5. **말은 현장 용어로, 경고는 필요한 곳에 한 번.**

대비(흰 바탕 기준, 계산값): 남색 14.6 · 보조 7.6 · 파랑 6.2 · 주의 5.0 · 완료 5.0 · 위험 6.5 · 주의/완료/위험 글자-연한 바탕 4.5~5.3. 하늘색(2.1)과 구분선(1.5)은 글자에 쓰지 않는다.

현재 초록(#225d4c)을 유지하는 대안도 가능하나, 브랜드 자산과 맞추는 것을 권장(결정 필요 1).

### 3.2 글꼴·크기

- **Pretendard**(SIL OFL, 무료 배포 가능)를 `public/fonts/`에 woff2로 포함 — CSP(`font-src 'self'`)를 바꾸지 않고 모든 기기에서 같은 모양. 숫자는 `font-variant-numeric: tabular-nums`(금액·수량 정렬).
- 크기 단계 6개만 사용: 12(메타) · 14(본문·컨트롤) · 16(휴대폰 입력·패널 제목) · 18(섹션) · 22(화면 제목) · 28(홈 숫자). **12px 미만 금지**, 휴대폰 입력칸은 16px(확대 방지).

### 3.3 간격·모양

- 간격 4px 배수(4·8·12·16·24·32). 화면 여백 PC 32 / 휴대폰 16.
- 모서리 6px(입력·버튼) / 8px(카드). 그림자는 떠 있는 것(메뉴·하단 바)에만.
- 터치 대상 최소 44×44px. 읽기 폭 최대 760px(양식), 표·문서는 넓게.

### 3.4 공통 컴포넌트 (처음 만들 10개)

`PageHeader`(제목·상태·주 동작) · `Section` · `Field`(라벨·도움말·오류를 칸 바로 아래) · `Button`(주/보조/위험/텍스트) · `Notice`(정보·주의·위험·성공, 한 줄 + "자세히") · `StatusBadge`(작성 중·제출·확정·마감 4종만) · `ConfirmBar`(확인창 대체: 화면 안 확인 + 취소) · `EmptyState` · `TechDetails`(ID·버전·해시·이력 접힘) · `SaveBar`(휴대폰 하단 고정 저장 + 저장 상태·오프라인 안내).

## 5. 사용 흐름 개선

| 흐름 | 지금 | 개선 |
|---|---|---|
| **TBM** | 긴 한 화면 양식 → 참여 링크 → 명부 → 확정이 한 페이지에 섞임 | 3단계 탭: ① 내용 ② 참여(QR·명부) ③ 확정. 진행 표시와 단계별 저장 상태 |
| **안전업무일지** | 1~5번 번호 섹션 한 줄, 참조 집계가 입력보다 먼저 | 입력 먼저, 자동 집계는 오른쪽(PC)/접힘(휴대폰) "참고" 영역. 하단 SaveBar |
| **점검** | 문항마다 select + 의견칸 | 문항 카드에 양호/불량/해당없음 큰 3버튼(현장 한 손 입력), 불량일 때만 의견·사진 |
| **사진 보드·사진대지** | 편집 도구가 사진 아래 긴 버튼 줄 | 사진 위 떠 있는 도구 막대(회전·강조·확대), 선택한 강조에만 크기/삭제 |
| **비용 월마감** | 원장·증빙·출력·마감이 각각 다른 버튼 화면 | 월 화면 상단 4단계 진행 막대(입력 → 증빙 → 출력 전 확인 → 마감)와 단계별 남은 일 |
| **확인창 72개** | 브라우저 기본 `confirm` | 되돌릴 수 있는 동작은 바로 실행 + "실행 취소" 알림, 되돌릴 수 없는 동작(확정·마감·제출)만 `ConfirmBar`로 결과를 문장으로 보여 주고 확인 |
| **오류** | 화면 맨 위 한 곳 | 칸 오류는 칸 아래, 저장 실패는 SaveBar 옆, 전체 오류만 상단 |

## 6. 문구 원칙

1. **경고는 화면당 최대 한 줄**, 근거·법적 범위는 `Notice`의 "자세히"로 접는다. 같은 면책을 버튼·양식·인쇄에 반복하지 않는다. (380개 → 목표 60개 이하. 인쇄물·법적 고지·P-02 공학 경고처럼 반드시 보여야 하는 것은 목록으로 따로 관리)
2. **내부값은 `TechDetails`로**: UUID·버전·해시·원시 JSON 이력은 기본 접힘, 관리자만.
3. **현장 용어 용어집**(예시):

| 지금 | 바꿀 말 |
|---|---|
| 참조 취합 | 관련 기록 불러오기 |
| 명시 연결목록 저장 | 연결한 지출 저장 |
| 미검사 원본 다운로드 | 원본 파일 받기 |
| 고정 기록 / 스냅샷 | 확정본 |
| 정정 초안 | 수정본 만들기 |
| 기록 확정 | 확정 |
| 표시본 | 미리보기 사진 |
| 수기 ○○ | ○○ (수기 여부는 화면 설명 한 줄) |
| 버전 충돌 | 다른 사람이 먼저 고쳤습니다 |
| 출력 전 확인 | 인쇄 전 점검 |

4. 버튼은 동사로 끝낸다("저장", "확정", "인쇄") — "~하기 ↗" 금지. 영문 eyebrow 전부 삭제.

## 7. 실행 방법

### 7.1 원칙
- **전면 재작성·새 UI 라이브러리 도입 금지.** 서버 인가·버전 충돌·불변 기록·오프라인 초안 동작은 그대로 두고 **겉(토큰·컴포넌트·문구·배치)만** 바꾼다.
- **화면 하나 = PR 하나.** 매 PR에 PC·휴대폰(에뮬레이터 포함) 전·후 캡처.
- **시험 호환:** E2E 40개는 라벨·역할 이름으로 찾는다. 문구를 바꾸는 PR은 같은 PR에서 E2E도 고치고, 접근 가능한 이름은 의미가 유지되게 한다.

### 7.2 단계

| 단계 | 내용 | 산출물 | 검수 기준 |
|---|---|---|---|
