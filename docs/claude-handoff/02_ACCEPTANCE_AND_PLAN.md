# 단계별 구현 계획·요구사항 추적·완료 기준

이 문서의 순서와 신규 설계는 **구현 제안**이다. 전체 기능 방향은 사용자 요구이고, 우선순위 세부는 인수자가 실제 의존성과 사용자 선택을 대조해 조정한다. 문서 작성 단계에서는 코드를 실행하거나 원개발본을 변경하지 않았다. 게시 범위는 문서 전용 브랜치·초안 PR의 Markdown 6개이며 제품코드·CI 설정은 변경하지 않는다.

## 2. 단계0 — 인수 기준 고정, 읽기만

1. 사용자 작업트리/브랜치/원격을 확인하고 main/PR head를 기록한다. PR 상태를 재조회한다.
2. 공개본과 인계본의 역할을 구분한다. 원개발본 세부 docs는 역사 문구를 포함하므로 최신 실제코드와 충돌시 표시한다.
3. 원앱 기능자료·허용된 샘플·실제화면 유무를 목록화한다. 미확보샘플을 임의 제작해 '원본'으로 부르지 않는다.
4. 요구추적표와 보안/운영 미해결목록을 작성하고 첫 기능을 정한다.

완료: 시작커밋·채택할PR범위·원앱비교근거·미확정결정이 명확하다. 이 단계에서 자동병합/배포/운영DB 접근은 하지 않는다.

## 3. 단계1 — 안전한 기준선과 공통 사용성

**구현 제안:** SEC-LOCAL-01의 파일생성/기존폴더/WindowsACL 위협모델을 정리하고 수정안을 독립검토한다. Windows 실패2건을 환경제약과 제품결함으로 각각 분류한다. symlink 권한을 관리자 실행으로 우회하거나 시험을 skip하여 녹색으로 만들지 않는다. PR의 bounded upload·ZIP 경로 검증이 유지되는지 확인한다.

공통 현장선택과 dirty/busy/409 입력보존, 오류표시, 접근성·모바일 메뉴를 검증한다. 업무별 현재권한을 출력·파일다운로드·receipt재생까지 확인한다.

완료: OS별 파일권한 실제증거, 철회/세션/CSRF/다현장 음성사례, 기존 DB56와 snapshot 호환, PR 기준 회귀결과가 기록됨. 미완료가 있으면 해당환경 배포 금지 사유로 남긴다.

## 4. 단계2 — 기존 앱 기능 보존을 한 업무씩 완성

권장 순서(제안): SC 잔여검수·유사UX → EDU/회의록/일지/점검의 연결과 출력 → 사진대지 → 계획문서 확장. 사용자가 다른 우선순위를 주면 변경 가능하다.

업무마다 다음 묶음으로 구현한다.

1. **화면:** 실제 사용할 사람의 시작점/버튼순서/입력도움말/오류/결과를 먼저 정의한다. SC는 원화면과 비교하고 다른앱은 업무가 더 쉬워지는 구조를 제안한다.
2. **입력:** 필수/선택/미입력/0/해당없음/단위/길이/목록상한·파일상한을 명시한다.
3. **처리:** 서버권한/동일현장/현재버전/중복key·transaction·전체rollback을 구현한다.
4. **보관:** 현재참조와 고정snapshot을 분리, 정정은 원기록보존·새버전·필요한참여/서명초기화.
5. **출력:** 저장내용과 동일한 숫자·단위·텍스트·첨부목록을 출력한다. 과거마감/보관본은 현재값으로 재작성하지 않는다.
6. **검사:** 합성fixture→단위/API→브라우저→실제PDF→원앱비교→사용자수용.

완료: 해당 하위기능의 입력부터 출력까지 실행증거가 있고 남은 기능이 명시된다. 구현파일이 생겼다는 것만으로 완료하지 않는다.

## 5. 단계3 — QR·서명·동의 위치 및 오프라인

개인정보/본인확인/대리/보존·거부대안 정책을 먼저 확정한다. 참여원장과 관리자수기기록을 분리한다. 서명문서hash·개정무효화, QR만료/폐기, 권한철회를 구현한다. 위치 미동의/사용불가를 숨기지 않는다.

오프라인은 별도 위협모델과 기기저장정책 후 구현한다. 테스트는 서버저장→통신차단→초안작성→권한변경→재접속→충돌복구 순서로 수행한다. 지원하지 않는 기능은 온라인필요로 안내한다.

완료: Android Studio 에뮬레이터에서 실제 클릭·키보드·권한거부·파일/카메라·QR진입 검증, 허용된 실제 단말/브라우저검증, 서명재사용 차단·동의이력·중복참여 방지가 증거로 남음. 에뮬레이터 통과가 실제 모든기기 통과는 아니다.

## 6. 단계4 — 공학계산과 선택형 AI

### 공학

식의 이름/출처판본/입력차원/적용조건/계수/환산/반올림/최대값/오류처리/정답사례를 식별한다. 원자료 의심참조는 검토자 결론을 받아야 하며 임의수정하지 않는다. 계산 결과는 문서입력과 연결하되 미검증상태에서 안전/합격표시를 하지 않는다. 정상·경계·단위혼합·누락·분모0·표밖입력에 대한 독립 oracle를 사용한다.

### AI

기본OFF, 수기기능 유지, 명시호출, 최소정보, 모델/버전·입력출처·결과검수표시. AI제안→diff→사용자승인→기존권한/버전/transaction 적용. 타임아웃/비용한도/잘못된응답/오래된원본은 기존자료를 보존한다. 공급자·전송·보존 정책 결정 전 네트워크 호출을 추가하지 않는다.

완료: 공학은 전문검토와 계산검증, AI는 별도 승인·비활성동작·출처/비용/실패복구가 각각 확인된다. 한쪽 통과로 다른쪽을 완료하지 않는다.

## 7. 단계5 — 출력·독립검토·복구·배포 수용

- 알PDF에서 실제 결과를 열고 한글폰트/긴문장/표/사진/가로세로/머리·꼬리/페이지넘김/말미잘림을 확인한다. 단순HTML 문자열검사는 대체가 아니다.
- 비용 합계/월/항목·교육 시간/대상·점검 항목·회의결정/후속·계획값/단위·사진caption을 저장본과 대조한다.
- 별도 복구디렉터리에서 DB+BLOB hash/FK/현재schema/세션무효화/recovery gate를 검증한다. 운영DB 교체는 별도 승인을 받는다.
- 독립보안검토는 최신변경커밋과 검사범위를 기록하고 구현자 시험과 구분한다. 이미지/PDF 디코딩·업로드·공개게시·민감정보 변경은 재검토한다.
- HTTPS/환경비밀/계정발급·회복/MFA/보존삭제/모니터링·용량·부하/장애대응/라이선스/실데이터 사용·배포승인 체크리스트를 채운다.
- 사용자 UAT(실제 업무를 따라 사용해 보는 최종검사)를 통과한 기능만 수용 처리한다.

완료: 승인된 배포대상·버전·실행환경·백업/되돌림·사용자수용·남은제약을 함께 발표한다. PR병합이나 CI 성공만으로 배포완료라고 하지 않는다.

## 8. 실행할 검사 명령 — 인수 이후 승인된 환경에서만

아래는 제안된 명령이며 **이번 문서 작성에서 실행하지 않았다**. 설치/프로세스 실행에 대한 사용자 권한과 AGENTS.md를 먼저 확인한다.

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

`npm run check`는 lint/typecheck/test/build 묶음이다. E2E는 Playwright 설정·테스트서버·포트·합성계정 정책을 읽고 실행한다. 계정발급/백업/복원 명령은 docs와 옵션을 먼저 확인하며 실제DB 기본경로를 추정해 실행하지 않는다. Windows/Linux 결과는 별도 기록한다.

검사마다 커밋SHA, OS/Node, 명령, 시작/종료시각, 성공/실패수, 실패원문 위치, 재현조건, 변경전후를 남긴다. skip·설정완화·권한상승으로 결과를 숨기지 않는다. 실행실패·미실행·결과미확인은 서로 다른 상태다.
