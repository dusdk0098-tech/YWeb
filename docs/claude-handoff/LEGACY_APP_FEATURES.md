## 0. 이 문서의 읽는 법과 최우선 UX 지시

- **기존 문서 확인**은 해당 저장소 README/설계/구현 문서에서 기능 계약을 읽었다는 뜻이다. 실제 설치·서명·배포·Windows/모바일 실행 성공을 뜻하지 않는다. 이번 조사에서는 앱이나 시험을 실행하지 않았다.
- **통합 구현 제안**은 Claude Code가 앞으로 구현할 계약이며, 기존 앱의 기능으로 확정해서는 안 된다. 최신 통합 원개발본 `docs/COVERAGE_CHECKPOINT.md`와 업무별 계약·실제 코드를 대조한다. 초기 `FEATURE_MATRIX.md`만으로 현재 구현 여부를 판단하지 않는다.
- **사용자 최우선 UX 지시:** SC는 기존 화면 구성과 조작 순서를 최대한 비슷하게 유지한다. 다른 앱은 기존 UI를 복사하지 않고 편리한 업무 중심 구조로 재설계한다. 기능·데이터 의미·검증 경계는 UI 변경 때문에 사라지면 안 된다.
- 아래 시험은 **앞으로 요구할 수용 기준**이지 이번 실행 결과가 아니다. 읽기 가능한 원문도 과거 상태·설계와 구현 완료 주장이 섞여 있으므로 코드와 exact commit 시험을 재확인한다.
- 원본 앱의 로컬 JSON/SQLite와 새 웹앱 서버 원장은 별개다. 자동으로 공유·이관된다고 가정하지 않는다. 계정/현장/파일/버전/ID 매핑, 임포트 미리보기, 중복·충돌 처리, 롤백을 별도로 설계한다.

### 화면과 조작을 보존할 기준

실제 HTML의 화면 선택 순서는 **대시보드 → 현장 설정 → 예산 및 전회누계 → 금월 사용내역 → 항목별 상세 → 인건비 조회 → 안전용품 수불부 → 사진대지 → 출력 미리보기**다. 이를 웹 SC 영역의 기본 정보구조로 삼는다. 전역 검색은 별도 새 탭이 아니라 명령 서랍이다.

PC에서는 고정 좌측 탐색, 고밀도 표, 고정 입력 패널, 표 내부 스크롤을 유지한다. 원설계는 1280px 이상 고정 사이드 탐색, 1040px 이하 로고 옆 화면 선택으로 전환한다. 원설계 토큰은 사이드바248px, 기본입력40px/컴팩트32px, 표행40px, 4px 간격 단위다. 회백색 작업면·짙은 남청색 탐색·청색 동작 강조, 황색은 경고 전용이다. 숫자 우측 정렬·tabular numerals, sticky 표 머리글, 선택행 표시를 유지한다. 장식적 카드 위주로 바꾸지 않는다.

**필수 보존 행동**: 순수 탭 전환은 6개 편집 폼의 미저장 내용과 pending/removed 첨부·사진 선택을 버리지 않는다. 행/항목/월/가져오기/복원 교체에는 공통 저장·폐기·취소 확인을 제공한다. 저장 완료 영수증 전에 다음 행으로 이동하지 않는다. 마감월은 명시적 잠금 배너와 읽기전용 입력, 사유 있는 재개를 제공한다. 사전점검 오류는 정확한 월/행/필드로 연결하고 이미 삭제된 대상 대신 임의의 첫 행을 선택하지 않는다. 비동기 늦은 응답은 새로운 월·선택·초안을 덮지 않는다.

### 출력 의미와 웹 이전

기존은 빈 원본 xlsm에 COM으로 값을 채우고 같은 통합문서를 PDF로 변환한다. 기본14쪽과 항목별 사진대지, 초과행 연속시트, 모든 연속 페이지의 동일 총합, 문서별 선택 인쇄가 계약이다. 실제 PDF iframe 미리보기와 출력 문서/페이지 맵을 사용한다. 생성 중 저장된 장부를 한 번 복제해 같은 입력으로 모든 출력을 만든다. 출력 없음/생성중/현재일치/저장변경/다른월/실패를 구별하고 오래된 PDF를 현재본으로 인쇄하지 않는다.

**웹 제안:** COM 의존을 브라우저/서버 출력 서비스로 바꿀 수 있지만 입력→집계→미리보기→선택 인쇄의 친숙한 흐름, 업무내용과 계산 동일성은 유지한다. 기존 xlsm/VBA 또는 페이지 수를 무조건 그대로 재현했다고 주장하지 않는다. 출력 동등성 샘플과 허용 차이를 명시한다. 비용과 물리수량을 무조건 같은 값으로 치환하지 않는다.

**현재 통합본과 차이:** `docs/COSTS.md`, `COST_BATCH.md`, `COST_SPLITS.md`, `COST_EVIDENCE.md`, `COST_BASELINES.md`, `COST_OUTPUT_FRESHNESS.md`, `STOCK_MINIMUMS.md` 및 관련 `server/cost-*`, `src/Cost*.tsx`에 수기 원장/마감/분할/증빙/기준본 일부가 있다. 원본 SC 전체 동등성, 인건비 원형, 사진대지, 원본 Excel import/output, 실인쇄/복원은 별도 갭이다. 기존 자동입고를 새 웹에 그대로 가정하지 말 것: 새 구현은 별도 물리수량을 명시하는 비용출처 입고 계약이다.

**수용 시험:** 같은 fixture의 예산/전회/금월/누계/분할 합계, 마감월 쓰기 차단, 다음월 이월과 과거 snapshot 불변, 음수/최소재고, TSV 오류행·중복·UNKNOWN, 탭전환 초안보존·IME·키보드·좁은화면·확대, 긴명칭/초과행/사진0·홀수·12장초과 PDF, 파일누락·출력stale·다른월, 복원 실패 원본보존. 단위시험과 실제 PDF/Excel/native 수용을 별도 기록한다.

- **기존 흐름:** 사진 추가→보드 초안→내용/배치 편집→준비 확인→PNG 또는 PDF 저장. 동일 Canvas2D scene을 화면과 출력에 사용한다. 결과유형 전환이 사진·회전·공통메타를 초기화하지 않는다. 실행취소/다시실행과 출력 실패 뒤 작업 보존이 있다.

- **연동:** 기존 Electron 사진/output IPC와 Launcher 승인 실행. 웹에서는 권한 있는 파일 업로드·디코딩·scene 저장·서버/브라우저 출력 API로 재설계한다. Windows 폴더 접근을 웹 기본 기능으로 가정하지 않는다.
- **통합 UI 제안:** 사진 선택/업로드→선택 사진 편집→결과검토 3단계, 모바일 터치 트레이와 큰 이동/회전 조작, PC 드래그/키보드 병행. 기존1920px 최소창을 웹 요구로 가져오지 않는다. SC 사진대지와 사진 원본을 공유하더라도 문서별 배치/설명은 별도 version으로 저장한다.
- **현재 갭:** 통합본의 N 전용 실제 사진 editor/Canvas scene/PNG·PDF 동등성은 확인된 구현 범위가 아니다. 예정 메뉴를 완성 기능으로 세지 않는다.
- **수용:** EXIF 회전·세로/가로·긴이름·선택제외·순서·undo/redo·강조 좌표, 결과 전환 보존, 업로드 실패/재시도, 출력 취소 보존, 한글/사진많음/메모리, 화면과 출력 동일 scene, 접근성. 원형 강조는 화살표1단위/Shift10단위 등 키보드 대안을 제공한다.

## 10. Claude Code 작업분해와 통합 데이터 계약

1. 앱별 위 기능을 작은 acceptance ID로 나누고 `원본 근거 → 새 API/DB/UI → 자동시험 → 실제 수용` 추적표를 만든다. 원본 이름만 복사한 메뉴는 미구현이다.
2. 공통 Site/Company/Worker/Equipment/File/DocumentVersion 식별자를 먼저 정한다. 사진/첨부는 파일원본과 업무참조를 분리하고 동일 파일을 연결해도 기록의 금액/수량/참석을 중복 생성하지 않는다.
3. 모든 서버명령은 current user/site scope, revision, requestId를 검사한다. 수락 영수증이 없는 응답불명은 성공도 실패도 아니며 저장본 재조회로 판정한다.
4. 승인/마감/보관은 변경불가 snapshot, 보완은 새 revision으로 표현한다. 과거문서의 인원/장비/내용/첨부가 현재 원장 수정으로 바뀌지 않는다.
5. SC 화면/흐름은 위 원형을 기준으로 비교 시안을 만든다. 그 외는 오늘할일→작성→검토→출력/전송의 단순한 흐름으로 다시 설계하고 원기능 손실 대조를 수행한다.
6. AI는 선택형 보조 입력/검토 제안으로 분리한다. AI를 끈 상태에서 모든 핵심 수기업무가 완료되어야 하며 자동승인·안전판정·마감·외부발송을 하지 않는다. 제안의 출처와 사용자가 수락한 값만 업무기록으로 저장한다.
7. 인쇄는 저장 version만 대상으로 미리보기/생성시각/원본version/stale를 표시한다. 앱별 원형과 내용·합계·사진·표·폰트를 비교하고 별도 PDF/실프린터 증거를 남긴다.
8. 작업순서는 기존 구현 재사용성 조사→SC 유사UX 계약 및 핵심업무 갭→다른 모듈사용성 재설계→파일/출력/모바일/연동→이관/복구·실사용검수다. 문서만으로 개발완료를 선언하지 않는다.

## 조사 제한

원격기본브랜치의 위 README/설계/구현·SC 실제 HTML을 읽었으며 전체 앱 소스를 exhaustive audit하거나 앱을 실행하지 않았다. 이 문서는 기능인계의 근거목록과 상세구현 체크리스트다. 원격repo 링크는 움직이는 main이며 구현 시작 때 commit을 고정해야 한다. 비공개 교육원문·실데이터·대화전문·인증정보를 이 문서에 복사하지 않았다. 기능 조사 단계에서는 원본저장소·페이지·PR·CI·설정을 변경하지 않았다. 이 공개본의 게시는 별도 문서 전용 브랜치·초안 PR로 한정한다.

## 11. 처음 쓰는 사람을 위한 쉬운 기능 설명

아래의 **누르는 버튼 이름은 웹앱 설명용 제안**이다. 실제 원앱의 정확한 버튼 문구를 모두 확인했다는 뜻은 아니다. SC는 실제 화면의 기존 버튼 문구와 순서를 먼저 대조한 뒤 최대한 유지한다. 나머지는 사용자가 쉽게 이해할 말로 재설계한다.

### 화면에 반드시 보여 줄 쉬운 상태말

- **아직 저장하지 않았어요:** 입력칸에는 있지만 서버가 받은 기록은 아니다.
- **저장됐어요:** 서버의 저장 영수증을 확인했다. 제출·승인까지 됐다는 말은 아니다.
- **저장 여부를 확인하고 있어요:** 통신이 끊겨 결과가 불명확하다. 바로 같은 요청을 다시 보내 중복 만들지 않는다.
- **검토를 기다리고 있어요:** 담당자가 확인해야 한다.
- **옛날 자료로 만든 출력이에요:** 장부가 바뀌었으므로 현재내용과 비교하거나 다시 만든다.
- **이 자료는 아직 확인되지 않았어요:** 파일을 붙였다고 안전검사·진위·법적요건까지 확인된 것은 아니다.

이 쉬운 설명을 실제 도움말/빈화면/오류메시지에 연결하되, 법적판정·안전보증·자동완료를 과장하지 않는다.
